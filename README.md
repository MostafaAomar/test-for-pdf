# تعلّم تفاعلي — إصدار v8 المبسّط للمبتدئ

تطبيق الطالب عبارة عن **HTML + CSS + JavaScript Vanilla + JSON**، ويمكن استضافته على **GitHub Pages**. لا يحتاج الطالب إلى Node.js أو npm. يمكن للمطوّر استخدام Node.js للتشغيل المحلي أو أدوات الاختبار فقط.

## الفكرة ببساطة

- **GitHub Pages:** يستضيف واجهة التطبيق وملف الفهرس الصغير `lessons/index.json`.
- **Google Drive أو رابط ملفات خارجي:** يحتفظ بملفات PDF والصوت الكبيرة، فلا تضطر إلى إضافتها إلى ملفات التطبيق.
- **لوحة الإدارة `manage.html`:** لا ترفع الملفات بنفسها، ولا تطلب تسجيل الدخول إلى Google. هي تحفظ بيانات الدرس وروابطه وتتيح تنزيل `index.json`.
- **النشر بعد إضافة درس:** استبدل `lessons/index.json` في مستودع GitHub بالنسخة التي نزّلتها من لوحة الإدارة. بعد تحديث GitHub Pages سيظهر الدرس للطلاب.

## رفع المشروع إلى GitHub Pages

1. أنشئ مستودعًا جديدًا على GitHub.
2. ارفع محتويات مجلد `interactive-learning` إلى المستودع كما هي، مع الحفاظ على المجلدات.
3. افتح **Settings → Pages**، واختر النشر من الفرع `main` ومن جذر المستودع `/`، ثم احفظ.
4. بعد اكتمال النشر، افتح رابط الموقع الذي يعطيك GitHub. واجهة الطالب هي الصفحة الرئيسية، ولوحة الإدارة في `manage.html`.

## إضافة درس جديد — أسهل طريقة

1. ارفع ملف PDF وملفات الصوت يدويًا إلى Google Drive أو أي استضافة ملفات تدعم الروابط المباشرة.
2. إذا استخدمت Google Drive، افتح مشاركة الملف واجعل الصلاحية **Anyone with the link / Viewer** إذا كان الدرس عامًا. لا تستخدم هذا الخيار للمحتوى الخاص.
3. افتح `manage.html` من موقعك.
4. اختر المادة والصف والوحدة، اكتب اسم الدرس، والصق رابط PDF. للصوت، الصق كل رابط في سطر مستقل.
5. اضغط **حفظ الدرس**.
6. اضغط **تنزيل index.json**.
7. في GitHub، افتح `lessons/index.json` في مستودع المشروع، واستبدله بالملف الجديد، ثم اضغط **Commit changes**.

بعد ذلك يقرأ كل الطلاب الفهرس المحدّث من الموقع. لا ترفع PDF أو MP3 إلى مستودع التطبيق؛ ارفع فهرس JSON الصغير فقط.

## ملاحظة مهمة حول Google Drive

الرابط الذي يفتح صفحة معاينة Google Drive ليس دائمًا رابطًا يستطيع عارض PDF الداخلي قراءته مباشرةً. عارض PDF يستخدم PDF.js ويحتاج رابط ملف يسمح بطلبات المتصفح (CORS). إذا لم يظهر PDF داخل التطبيق، استخدم رابطًا مباشرًا من مصدر يدعم CORS. إذا لصقت رابط ملف GitHub بصيغة `github.com/.../blob/...`، تحوّله لوحة الإدارة تلقائيًا إلى رابط `raw.githubusercontent.com`. للمطوّر الذي يريد قراءة ملفات Drive العامة مباشرة داخل العارض، توجد خانة **Google Drive API Key اختيارية** في لوحة الإدارة؛ لا يحتاج هذا المسار إلى OAuth Client ID ولا إلى تسجيل دخول أو صلاحية رفع ملفات. لا تضع أي كلمة مرور أو client secret داخل ملفات الموقع.

## تشغيل المشروع محليًا

للتجربة على الكمبيوتر، يحتاج المطوّر إلى Node.js فقط. على Windows يمكن تشغيل `START-WINDOWS.bat` ثم فتح `http://localhost:5173/` أو `http://localhost:5173/manage.html`. لا حاجة إلى `npm install` لتشغيل الموقع.

## ما الذي لا تفعله لوحة الإدارة؟

للحفاظ على المشروع بسيطًا وآمنًا، لا ترفع ملفاتك إلى Google Drive تلقائيًا ولا تعدّل مستودع GitHub تلقائيًا؛ لا يمكن لصفحة ثابتة على GitHub Pages أن تكتب إلى مستودعك من دون تفويض آمن. لوحة الإدارة تصنع الفهرس لك، وأنت ترفع ملف JSON الصغير إلى GitHub. هذا يتجنب وضع مفتاح GitHub خاص أو كلمة مرور في كود المتصفح.
